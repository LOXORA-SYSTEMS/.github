# Contributing to LOXORA SYSTEMS

Thanks for helping build reliable software. These rules keep our work consistent and safe.

## Workflow

1. **Pick or create an issue.** Every change starts with an issue.
2. **Branch from `main`** using this naming:
   - `feature/short-description`
   - `fix/short-description`
   - `chore/short-description`
3. **Commit clearly** using [Conventional Commits](https://www.conventionalcommits.org/):
   - `feat: add invoice export`
   - `fix: correct VAT rounding`
   - `docs: update setup guide`
4. **Open a pull request** into `main` and fill in the template.
5. **Get one review** before merging. Never push directly to `main`.

## Standards

- Keep pull requests small and focused on one thing.
- Test your change before requesting review.
- Never commit secrets (passwords, API keys, `.env` files).
- Update documentation when behaviour changes.
- Client repositories are **private**. Do not copy client data or code elsewhere.
